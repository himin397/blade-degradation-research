# Codex 艦隊レビュー（fleet）

Claude Code が司令塔となり、Codex CLI を観点別の独立レビュアーとして複数並列起動する運用です。実装者（Claude Code）が自己検査すると設計意図に引きずられるため、独立視点を複数束ねて盲点を潰します。

出典：Zenn 記事「Claude Code + Codex fleet」（2026-07-10）を himinさんの環境（ChatGPT Plus 認証・codex-cli 0.142.5）に合わせて改変。

## 発動条件

以下のいずれかのときのみ実行します（CLAUDE.md「Codex 連携運用方針」の艦隊モード）：

1. himinさんが明示的に艦隊レビューを依頼した
2. CLAUDE.md の自主実行3条件のうち「重要な意思決定を含む変更」（不可逆・データ解釈変更・外部連携影響）に該当し、かつ単発レビューでは観点が足りないと判断した

軽微な変更・Q&A・学習タスクでは使いません。ChatGPT Plus の利用枠を消費するため、デフォルトは **3並列・最大2周**（=最大6呼び出し）に抑えます。

## 手順

### 0. 事前確認

```bash
codex --version   # codex-cli 0.142.x 以上
echo "OPENAI_API_KEY length: ${#OPENAI_API_KEY}"   # 0 であること（API課金回避）
```

出力先ディレクトリをレビュー対象プロジェクト直下に作成します：`<対象プロジェクト>/docs/codex/`（なければ作成）。既存の `codex-NN-*.md` を確認して次の連番 NN を決めます。

匿名化した複製を渡す場合は、漏れ検査の検査語に日本語表記のほかローマ字・略称・大文字小文字の違いを入れ、本文だけでなくコード内の識別子（保存キー・クラス名・ファイル名・コメント・属性値）も対象にします。符号名が本物の原稿へ逆流していないかも後で検査します（2026-09-29 追加）。

### 1. レンズ（観点）の選定

デフォルト3本。対象に応じて追加・差し替えます：

| ID | レンズ | 役割設定 | 向く対象 |
|---|---|---|---|
| SPEC | 仕様穴・エッジケース | 「仕様の抜けと境界条件の欠落を探せ」 | コード全般 |
| ATK | 攻撃者視点 | 「あなたの役目はこのコードを壊すことだ」 | 入力処理・認証・ファイルIO |
| MNT | 設計・保守性 | 「半年後の保守者として読み、負債を指摘せよ」 | コード全般 |
| DATA | データ整合性 | 「集計定義・単位・数値の意味の齟齬を探せ」 | 分析スクリプト・集計ツール |
| CLM | 主張強度 | 「根拠と主張の対応を検証し、過剰主張を挙げよ」 | 論文・研究文書・戦略文書 |

### 2. プロンプト作成（6要素・必須）

各レンズのプロンプトに以下をすべて含めます：

1. **役割明示** — レンズの役割設定（敵役化）
2. **読む対象** — ファイルを**絶対パス**で列挙
3. **スコープ限定** — 「指定リポジトリ以外は読むな」
4. **出力形式** — 指摘に `REV-<レンズID>-001` 形式の ID を振らせる
5. **根拠必須** — 「各指摘にファイルパスと行番号を付けよ」
6. **変更禁止** — 「ファイルを一切変更するな」（sandbox と二重の保険）

### 3. 並列起動

各レンズを Bash の `run_in_background: true` で同時起動します（3本を1メッセージで並列発行）：

```bash
codex exec \
  --sandbox read-only \
  -c model_reasoning_effort="xhigh" \
  --skip-git-repo-check \
  -C "/abs/path/to/target-repo" \
  --output-last-message "/abs/path/to/target-repo/docs/codex/codex-NN-<lens>.md" \
  "<6要素プロンプト>" < /dev/null 2>/dev/null
```

**注意（0.142.5 検証済み）**：
- 記事にある `-a never` は現行 `exec` に存在しない（exec は元々非対話）。付けると exit 2 で即死するので付けない
- フラグはプロンプトより前に置く
- パスはすべて絶対パス（相対パスだと出力が迷子になる）
- `< /dev/null` で stdin を閉じる（ハング防止）
- effort（推論の深さ）を必ず明示する（2026-09-29）。艦隊レビューは重要な変更で発動するので既定は `xhigh`。明示依頼で中身が通常のレビューなら `high`。利用枠が厳しい時も、重要な案件では effort を下げず並列数を減らす（下げる判断は CLAUDE.md の effort 基準に反するため、利用者に相談する）。指定が無いとグローバルフック `codex-effort.py` が止める
- 完了判定は **exit code**。出力ファイルの存在確認で判定しない（書き込み途中がありうる）

### 4. 回収・統合

全プロセスの終了後：

1. 各 `docs/codex/codex-NN-<lens>.md` を読む（無加工で保存されたものが一次記録）
2. Claude Code が統合レポート `codex-NN-synthesis.md` を同ディレクトリに作成：
   - 指摘を ID 付きで一覧化し、**採用/却下/保留を明示、理由を記載**
   - 複数レンズが重複指摘した項目は優先度を上げる
   - Codex の指摘を盲信せず、コードを実際に読んで裏取りしてから採否判定（CLAUDE.md 既存ルール）
3. himinさんへは統合レポートの要約を提示（生ログを貼らない）

### 5. 2周目（2周ルール）

修正を反映したら、確定前にもう一周レビューします。1周目のセッションを `resume` で継続すると文脈を保てます：

```bash
# セッション ID は ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl のファイル名末尾 UUID
codex exec \
  --sandbox read-only \
  -c model_reasoning_effort="xhigh" \
  --output-last-message "/abs/path/docs/codex/codex-NN-<lens>-round2.md" \
  resume <SESSION_ID> \
  "REV-XXX-001 と 003 は修正した。差分を再判定せよ。" < /dev/null 2>/dev/null
```

- resume 時もフラグは `exec` 直後・`resume` の前に置く
- 2周目で新規 P0 指摘が出ることがある（記事実績：権限バイパス級が2周目で初検出）。2周目クリアを完了条件とする

## 罠一覧（記事＋検証結果）

| 症状 | 原因 | 対処 |
|---|---|---|
| exit 2 で即終了 | フラグ位置誤り・存在しないフラグ（`-a` 等） | フラグは exec 直後、0.142.5 の `--help` で確認 |
| exit 0 なのに出力なし | mise 等シムの未 trust | 対象ディレクトリで codex を一度対話起動して trust |
| ハング | stdin 待ち | `< /dev/null` を必ず付ける |
| 出力ファイルが見つからない | 相対パス | `--output-last-message` は絶対パス |
| 空・途中のレビューを読む | 完了前読み込み | exit code を待ってから読む |

## コスト記録

`codex exec` 出力末尾のトークン消費を synthesis に記録します。Plus 枠の上限に近い場合は並列数を2に落とすか単発に切り替えます。
