# FRP 検証チェックリスト

CLAUDE.md「事実精度4原則」＋「検証運用ルール」の工程化。**本文の正は CLAUDE.md**。このスキルは実行手順のみを定める。対象成果物（直前の回答案・ドラフト）に対して以下を順に実行し、結果を回答に反映する。

## 手順

1. **主張の原子化**：成果物の主張を「1文1主張・反証可能な形」のリストに分解する。散文のままチェックしない
2. **3区分ラベル**：各主張に付ける
   - 検証済み（出典つき・今セッションで確認したもの）
   - 未検証の一般知識（検索で白黒つけていないと明示）
   - 判断・仮説（Proposal Policy の段階表示を併用）
3. **検証深度の下限チェック**（不足があれば今から検証するか、ラベルを落とす）
   - 制度的事実＝権威ドメインの一次資料1件
   - 統計・数値＝原データ（出典の出典）まで遡る
   - 論文の主張＝実物PDF精読（アブストラクト・検索サマリー不可）
   - 一般化命題＝検索1〜2回で確定しなければ「未検証の一般知識」へ降格
   - **環境値・計測値**（温度・湿度・回数・稼働時間）＝代表値の種類（最高／最低／平均／瞬間）を確認してから使う。最高値を「その温度が続く」前提で寿命・劣化に当てると大きく外れる（2026-09-13 追加）
   - **新たに測る・集める前に既存記録を探す**：日常・月次の点検票・ログ・帳票に同じ値がすでに溜まっていないか。あれば、対象・期間・単位・代表値の種類・測定間隔・欠測を確認し、今回の目的を満たす範囲は既存記録の集計で代替し、**不足分だけ**追加で測る。反復利用する抽出・集計はスクリプト化する（2026-09-13 追加）
   - **外部の手法（講座・書籍・仕様書）の再現**＝書き起こし・スライド・図・見本の複数の形で照合する。1つの形の強い語（「絶対必要」）だけで範囲を決めない。「必要か」と「どこに置くか」は別の問いで、後者が原典に無ければ実務の慣行と相手側の一次資料で決める（2026-09-13 追加）
   - **追記・更新・訂正の日付がある一次資料**＝本文より先にその追記を開き、結論が変わっていないか確かめる。同じ発行元の訂正記事・更新履歴も確かめる（訂正は冒頭の短い追記や別記事に置かれる）。日付だけ書き写して中身を読まず、訂正前の結論を根拠にした実例あり（2026-10-14 追加・ads の失敗事例から）
   - **検索の深さと手順**（2026-10-15 追加）：回答の冒頭の深さの宣言（CLAUDE.md 検証運用ルール）が質問に合っているか、宣言した深さの必須の工程（一次資料・引用の照合・反証・独立2件）が実施済みか未達かを照合する。WebFetch の答えから数値・条件・日付を採る時は、依頼文に「該当の文をそのまま引用して」と入れたうえで、**返った引用を取得した本文の該当箇所と前後の条件に照合する**。照合できなければ「原文未照合」とし、検証済みに含めない（引用の要求は補助。要約する側のモデルが本文に無いことを答えた実例あり）。組織名・人名つきの主張は、一次資料のページを開いて主体を確かめる。公開情報の検索が要る時、日本の話題は公式ドメインに絞った検索を1本入れ、日本語で一次資料に届かなければ英語でも検索する。反証方向検索の条件（手順4・各フォルダの検証運用ルール）に当たる主張で1件目が期待どおりだった時こそ、省かずに反対方向を1本足す。**終了の条件**：主要な主張の原典照合が済み、反証の条件に当たる主張の反対方向の確認が済み、出典どうしの重要な矛盾を処理したら終える。取得できない時や、独立した出典2件が要る主張（「念入り」の段階・「複数ソースで確認」と書く主張）で2件に届かない時は、不足を明記して終え、それに依存する断定は保留する（回数を満たしただけで終えない・条件を満たせないまま検索を続けない）。「その文書に何と書いてあるか」の帰属の確認は原典照合で済み、主張の内容を独立した資料で裏付ける確認とは別に数える。読めなかったページ（会員限定・動的な表示）は「読めなかった」と書き、「情報が無い」と書かない
4. **反証方向検索**（研究結論に効く主張のみ。条件の正は CLAUDE.md 検証運用ルール5）：①結論の否定形 ②結論語を含まない中立語 の1〜2本。使用クエリを回答に記録し、最も強い反証に回答内で応答する
5. **出典の独立性チェック**：「複数ソースで確認」と書く前に、各ソースが共通の上流の引き写しでないか確認。系譜が同じなら1件と数える
6. **効果量の二面提示**：平均差・集団差を判断に接続する場合、SD・CI 等の散らばりを併記。個人への転用には判別性能（AUC 等）を示す。示せなければ集団傾向に留める
7. **証拠の量と結論語の釣り合い**（2026-09-23 追加）：「確定」「解消」「習得」「動作確認済み」「再現」を使う主張ごとに、証拠の量（n・k/N・日付・条件）が同じ文にあるか確認する。判定は上から順：n≤2＝単発（観察・一例）／n 3〜9、または10以上でも同日かつ1条件＝少数（傾向・暫定）／n≥10 かつ別日または別条件、または事前に定めた基準を満たす照合＝十分（確認・確定・習得）。学習の習得は別日含む10問以上で失敗1以下・形式違い1問・過去の誤答型を含む。分析の確定は効果量・散らばり・標本の選び方を併記。ツールは試験範囲を明示。命題の種類で非対称（全称は1件の反例で崩れる、存在は1件で確認できる、習得・成功率・一般化は1件では書けない）。バグの存在確認は1件で可
8. **判断ログ記録**：「判断・仮説」ラベルの重要主張は `AIノート/判断ログ.md` に確度（高80%+／中50-79%／低<50%）と決着条件（判定方法・期限）つきで追記する。ただしファイル編集を伴わない相談・回答のみのやり取りでは、勝手に追記せず「追記候補」として回答内に提示する
9. **検証の足あと**：回答末尾に3区分の内訳を明示する。出典リストは「検証済み」のみをカバーする。深さを宣言した回答には検索0回でも「検索 n回（うち extended m回）・開いた一次資料 k件・委譲 j体」を1行添える（数え方は CLAUDE.md 検証運用ルールの検索の足あとの項。2026-10-15 追加）

## 成果物種別ごとの追加チェック（2026-09-05 追加・出所＝ads の失敗事例。Codex レビュー反映版）

該当する成果物にだけ適用する。「自己検証の材料が手元にあるのに使わなかった」型の取りこぼしを防ぐ。段階ごとに分け、各段階で該当項目だけ実施する。

### A. 提出前（このスキルの本体と同時に）
- **作る前の完了の条件**（2026-10-31 追加・親 claude1 から配布。CLAUDE.md「作る前の聞き返し」の対象の成果物では、回答の重要度や Codex レビューの実施・省略にかかわらず適用する）：①作り始める前（途中で対象に変わった時・条件が変わった時はその時点）に完了の条件5項目（入力・出力・使う場面・合格の判定・やってはいけないこと）を書いたか ②決まらない条件・解釈が複数ありうる条件で作る物が変わる時に、止めて聞き返したか（推測で埋めて作り始めていないか）。回答の後も決まらない条件に依存する部分を作っていないか。ただし himinさん が明示的に「任せる」とした条件は聞き返し不要で、任せた発言と採用した仮の値が報告にあるかだけを確かめる ③完了報告に条件ごとの**根拠**（指示／回答／仮）と**試験**（通過 k/N・失敗・未試験）の2欄があるか、を確かめる。①②を飛ばして作っていたら、完了の条件を書いたうえで、**himinさん の指示・回答で裏付けられない条件を列挙**し、その中で作る物が変わるものを確認待ちとして報告に書く（推測で書いた条件と作った物は一致して当然なので、ずれの有無では足りない。作り直すかは回答を受けて himinさん が決める）
- **新しい機能・道具・自動化の案を出す**：案を並べる**前に**、そのフォルダの洗い出し文書・README・既存の画面やコマンド（コード）を読む。すでにあるものは「済：所在（画面・コマンド・コード）」、一部だけあるものは「一部済：足りない範囲」と書いて出す。記憶と設計文書だけで並べると、既存の機能を新しい案として出す（作る前に確かめる決まりだけでは案の段階の重複を防げず、再発した実例あり。2026-10-14 追加・ads の失敗事例から）
- **道具で作った記録・成果物を手で直す**：直す前に、その欄に掛かっている決まり（下書きコマンドの説明・README の変更履歴）を読む。利用者が明示した決まり（書かない話題など）は注意書きのままにせず、**書く道具と書き出す道具の両方の検査**に入れる（判定は共通の関数にして両方から呼ぶ。下の B の項）。コマンドの説明にしか無い決まりが手直しで破られた実例あり（2026-10-14 追加・ads の失敗事例から）
- **Codex レビューの原本・再利用する検査・判断の根拠にした資料を作った**（作業の種類を問わない）：報告の前に正のフォルダ（対象の `docs/codex/`・`tests/`・設定のバックアップ・ノートの出典欄）へ移し、報告に保存先を書く。スクラッチパッドは会話の終了・再開で空になる（Codex の原本と検査、一括書き換え前の退避と調査資料が消えた実例あり。2026-10-14 追加・ads と claude1 の失敗事例から）
- **数値表と導出式が併存する文書**：式で表の各行を再計算し一致を確認する（不一致＝式か表のどちらかが誤り）
- **他文書からの要約・数値の引き写し**：自分が過去に書いた文書も「実物」。記憶で圧縮せず原典を開いて照合する。**数え上げ（「全部でN個」）は原典との一致ではなく元データ・対象ファイルから再集計する**（原典自体の件数が誤っていた実例あり）。条件の集約（「N件が条件Xを満たす」）は元の各項目の条件・例外・留保と照合する
- **見本値を含む入力・設定**（雛形・記入例・設定ファイル）：注意書きだけで対策完了としない。入力元を1か所に集約する／見本語を部分一致で機械的に弾く／生成物を実物で確認する、を該当性に応じて**組み合わせる**（設定から読むだけでは設定内の見本値がそのまま出る）
- **機械的検査が内容を確認できない成果物**（画像・PDF・音声・フォント埋め込み）：表示・再生して目視／試聴する工程を入れる。自動で開くのは補助であって確認の完了ではない
- **公開される成果物**（HTML・PDF・スライド・配布物）：先に読者と公開範囲を定める。内部情報（根拠の引用・個人的事情・内部語）を持つ作業版から公開版を作る場合は、作業用と公開用を分けて公開版を機械的に生成し、除去後も必須要素が残っていること・内部語が無いことを検査する。内部情報を含まない単発の配布物には分離は不要。**禁止語の走査**（2026-09-13 追加・Codex 指摘で改訂）：編集方法（生成／手編集）ではなく**形式に応じて**検査する。テキスト（md・HTML・CSV）は `grep -rc … フォルダ/ | grep -v ":0$"` の**再帰形**で走査する（`フォルダ/*.md` のグロブはサブフォルダを拾わない）。Excel・PDF は内容を抽出して走査し、**抽出に失敗した領域・未検査の領域は合格にしない**。禁止対象は案件固有の**役割口調の一人称・二人称そのもの**と内部語（相談相手・人物・会話文脈を示す語）。正当な引用や読者向けの「あなた」は、箇所と理由を限定して個別に確認する（一律の機械失敗にしない）。禁止語リストに個人名は載せない（列挙自体が記録になる）。生成スクリプトは**一時出力を検査してから正式出力へ置き換え**、失敗時は今回の一時出力だけを削除する（既存の正常版を消さない）。生成物に漏れがあれば HTML ではなく**生成スクリプト側を直して再生成**する。**方針（書かないもの・載せないもの）を変えた時**は、下書きだけでなく公開済みの出力フォルダも含めて機械検索し、食い違いを探す（2026-09-29 追加）。**道具が自動で git commit する**（公開の経路・ホスティングへの反映など）時は、その処理に `-c user.useConfigOnly=true` を組み込み、名前とメールの設定が無い時に止まることを試験する（設定が無いと git は OS の利用者名・ホスト名から作者を推測し、実名が履歴に残りうる）。止まったら、そのリポジトリにだけ屋号などの名前と noreply アドレスを設定する手順を示す。これは推測を止めるだけで、すでに設定された名前や環境変数による指定は防がないので、作者欄は別に確かめる（2026-10-14 追加・ads から）
