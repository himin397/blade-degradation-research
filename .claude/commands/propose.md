# propose — 改善提案を親フォルダ（claude1）へ共有する

使い方：`/propose <一言>`（例：`/propose DOI 照合を reference_audit の必須欄にする`）

このフォルダで気づいた運用ルールの改善点・失敗事例・便利な工程を、`docs/改善提案.md`（追記専用）に型どおり追記する。子フォルダは他フォルダを編集できないので、提案箱に書いて親の回収（`/sync-rules`）を待つ。処理状態は親の台帳 `claude1/AIノート/共有知見台帳.md` が持つ（読むのは可）。

## 手順
1. 直前の作業から、共有する価値がある知見を**1件に絞る**（複数あれば1件ずつ実行する）。基準＝他のフォルダでも同じ失敗・同じ手間が起きうるか（引用検証・文書精読・Codex 運用の知見は特に共有価値が高い）
2. **重複確認（追記の前）**：`docs/改善提案.md` の既存節と、親の台帳 `claude1/AIノート/共有知見台帳.md` を読む。同趣旨があれば新規節を作らず、既存節に「同事例を再発（日付）」と1行足して終える
3. **守秘チェック**：守秘区分D（公開してよい汎用知見）か。勤務先由来のデータ・サイト名・機器ID・未公開の研究結果を含むなら抽象化して固有情報を落とす。落とせないなら提案しない。研究の中身ではなく「進め方」を書く
4. **ID を振る**：`blade-YYYYMMDD-NNN`（今日の日付、NNN は同日の連番 001〜。既存節の ID を見て次の番号）
5. `docs/改善提案.md` 末尾に、同ファイルの型（見出し `## ID: … | 種別 | 日付`・内容・根拠・反映先・適用範囲）で追記する。状態欄は書かない（親の台帳が管理）
6. 報告：「提案箱に追記した（ID）。親フォルダの次回セッション開始時に未処理件数が表示され、`/sync-rules` で回収される」と伝える。自分では他フォルダの CLAUDE.md・設定を編集しない

## 書かないもの
- 研究の進捗・論文の内容（それはメモリと docs/ に書く）
- 一度きりの手順（再現性が無いもの）
