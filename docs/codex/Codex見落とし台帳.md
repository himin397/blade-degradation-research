# Codex 見落とし台帳（2026-10-31 から）

Codex のレビューを通った成果物で、使い始めてから見つかった不具合を1件ずつ書き、分類ごとの件数を数える。どこに穴が多いか（Codex の見落とし／採否の判断／見せていない修正／作る前の取り違え）を、四半期棚卸しで見る。
再現試験（当時の資料で Codex を流し直して見つけられるかを試す）はしない。Codex は別のフォルダの修正後のファイルや台帳を読めてしまい、正解を見ずに見つけたと保証できないため（2026-10-31 利用者の判断・Codex 2回の重大）。
記録の入口＝CLAUDE.md の Codex 節の1行と `/frp-check` C「使い始めてから不具合が見つかった」。守秘：成果物の名前と症状は、このフォルダの守秘の区分に従って書く。

## 分類（書く前に、当時の Codex の原本・採否表と、送った版の写しを開いて決める）
- **a＝Codex の見落とし**：送った版で不具合が成立していて（原因の箇所が送った資料の中にあり）、当時の原本に該当する指摘が無い
  - 要望の取り違えでも、当時送った資料（依頼文・仕様）に利用者の要望が書かれていて、実装と食い違っていたなら a
- **a′＝指摘済み・未対応**：当時の原本に該当する指摘があったが、Claude Code が却下・見送りした。誤ったのは採否の判断（採否の理由を併記する）
- **b＝見せていない修正**：送った版では不具合が成立せず、原因が最後のレビューの後に入った修正にある
- **c＝資料の外の取り違え**：仕様どおりに動くが欲しかった物と違い、その要望が当時送った資料に無かった（CLAUDE.md「作る前の聞き返し」の領域）
- **保留**：原因が複数で送った版で不具合が成立していたかを確かめられない時、または当時の原本・採否表・送った版・依頼文のどれかが残っていない時。分類できなくても記録は止めず、原因の箇所と欠けている資料を書く
- 対象外：Codex のレビューを通していない成果物（書かない）

## 書く欄
- 送った版：`codex_pkg.py` の `--keep` の場所と回（round-N）。2026-10-19 より前のレビューは git のコミット
- 依頼文：当時の依頼文の本文の写しの場所（原本と同じフォルダの `…_依頼文.md`。a と c を分けるのに使う。無ければ「依頼文なし」で保留の候補）
- 試験：同じ不具合を通常の試験に足したか（足した試験の場所）。台帳は穴の場所を数えるためのもので、再発を防ぐのは試験
