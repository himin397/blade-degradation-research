## Phase A: CNN基礎復習（完了: 2026-04-14）

### 合格ライン1: 「畳み込みとは何か」を30秒で説明

| 用語 | 意味 |
|---|---|
| 畳み込み（convolution） | 小さなフィルタ（例: 3×3の数値の塊）を画像上でスライドさせ、対応するピクセル同士を掛けて足すことで、局所的な特徴（エッジ、色の変化など）を検出する操作 |
| フィルタ（カーネル） | 「何を探すか」を決める小さな数値の塊。中の数値によって検出するものが変わる（縦エッジ、横エッジなど） |
| 特徴マップ | 「画像のどこにその特徴があったか」の地図。フィルタを画像全体にスライドさせた結果として出力される |
| プーリング（pooling） | 特徴マップの領域（例: 2×2）から最大値だけを残して圧縮する操作。位置の微妙なズレに強くなり、データが小さくなる |
| 抽象度が上がる | 層を重ねるごとに、大量の低レベル情報（ピクセル）を少数の高レベルな判断（「これはクラックだ」）に圧縮していくこと。曖昧になるのではなく、情報を統合していく方向 |
| 解像度（特徴マップの） | 特徴マップのマス目の細かさ。画質ではなく情報の粒度。プーリングを重ねるほど低くなる |

**30秒説明の要点**:
1. 小さなフィルタを画像上でスライドさせて局所的な特徴を見つける
2. それが特徴マップ（どこにその特徴があったかの地図）になる
3. 層を重ねるごとに抽象度が上がる（エッジ → パターン → 物体）

### 合格ライン2: 「学習率を変えると何が変わるか」を説明

| 用語 | 意味 |
|---|---|
| 損失関数（loss function） | 予測と正解のズレを数値化したもの。大きいほど予測が悪い |
| 教師データ（正解ラベル） | 人間が事前に「この画像のここにクラックがある」と付けたラベル。予測の後に答え合わせとして使う。先に見せるのではない |
| 勾配降下法（gradient descent） | 損失が小さくなる方向にフィルタの数値を少しずつ調整する方法。「予測 → 答え合わせ → 調整」のサイクルが唯一の学習手段 |
| 学習率（learning rate） | 1回の調整でフィルタの数値をどれだけ動かすかの幅 |
| バッチ（batch） | 学習データの中から数十枚をまとめて入力する単位。1枚ずつだとその画像のクセに引っ張られるため、まとめることで平均化する |
| エポック（epoch） | 学習データ全体を1周すること。30エポック = 同じデータを30周回して学習 |

**説明の要点**:
- 学習率が**大きすぎる** → 最適値を飛び越えて発散する（ボルトを回しすぎて行ったり来たり）
- 学習率が**小さすぎる** → 収束が遅すぎて時間切れになる（少しずつすぎて終わらない）

### 合格ライン3: Table 3bの「なぜmが悪いか」を説明

| 用語 | 意味 |
|---|---|
| 過学習（overfitting） | 学習データのクセまで丸暗記してしまい、未知データに対応できなくなる状態 |
| 汎化（generalization） | 学習データだけでなく、未知のデータにも通用する能力 |
| train / val / test | train: フィルタを調整する（学習する）。val: 学習中に未知データへの対応力を監視する（学習しない）。test: 最終評価に1回だけ使う（学習しない） |
| 過学習のサイン | trainの損失が下がるのにvalの損失が上がり始める状態 |

**説明の要点**:
- YOLOv8m（25.9Mパラメータ）はモデル容量が大きい
- 学習データは約700枚と少ない
- 容量が大きいのにデータが少ないと、データの本質的なパターンだけでなく個々の画像のクセまで丸暗記できてしまう → 過学習
- 結果: n（0.581）> s（0.575）> m（0.425）。モデルが大きいほど成績が悪い → ボトルネックはモデルサイズではなくデータ側

## Phase B: YOLOの仕組み（完了: 2026-04-15）

### 合格ライン1: 検出例画像で「何が出力されているか」を説明

| 用語 | 意味 |
|---|---|
| 画像分類 | 画像全体を見て「これは何か」を1つ答える（例:「クラックあり」） |
| 物体検出 | 画像中の「どこに」「何が」あるかを同時に答える。出力は複数可 |
| バウンディングボックス（BBox） | 損傷の位置と範囲を示す矩形 |
| クラスラベル | 検出されたものの種類（例: LE;ER, VG;MT, LR;DA, LE;CR, SF;PO） |

**説明の要点**:
- 物体検出の出力 = BBox（どこに・どの範囲で）+ クラスラベル（何が）
- 2D画像からは表面に見えている損傷の位置と種類まで。深さや内部状態は検出できない

---

### 合格ライン2: 「なぜYOLOは速いか」を30秒で説明

| 用語 | 意味 |
|---|---|
| 2段階方式（Faster R-CNNなど） | まず「怪しい領域」を探し、次にその領域が何かを分類する。精度は高いが遅い |
| 1段階方式（YOLOなど） | 画像全体を一度に処理して、位置とクラスを同時に出力する。速い |
| YOLO | "You Only Look Once"の略。一度見るだけで検出が完了する |

**説明の要点**:
- YOLOは1段階方式。画像を一度だけ見て位置とクラスを同時に出力するから速い
- Paper 1でYOLOを選んだ理由: パイプラインの一部品として速さ・シンプルさ・再現性が重要だった

---

### 合格ライン3: backbone/neck/headの役割を説明

| 用語 | 意味 |
|---|---|
| Backbone（背骨） | 画像から特徴を抽出する。CNNの畳み込み＋プーリングの繰り返しで、浅い層（細かい特徴）から深い層（大きなパターン）まで段階的に抽出 |
| Neck（首） | Backboneが抽出した異なるスケールの特徴を統合する。浅い層の細かい情報と深い層の広い情報を互いに補完させ、大小両方の損傷を検出可能にする |
| Head（頭） | 最終判断を出力する。BBox（位置・範囲）とクラスラベル（何の損傷か）を出力 |

**説明の要点**:
- 浅い層: 特徴マップのマス目が多い（解像度高い）、1フィルタの視野が狭い → 小さい損傷が得意
- 深い層: プーリングで圧縮されマス目が少ない（解像度低い）、1マスが広い範囲を代表 → 大きい損傷が得意
- Neckが両方を統合することで、大小両方に対応

---

### 合格ライン4: 「なぜパッチに切るとmAPが上がるのか」を説明

| 用語 | 意味 |
|---|---|
| パッチ | 高解像度画像を切り分けた小さな領域 |
| ピラミッドパッチ拡張 | 画像を複数のスケール（大きいパッチ・小さいパッチ）で切り分けて学習データを増やす手法 |
| 入力サイズ制約 | YOLOv8は640×640ピクセルに縮小して処理する。高解像度画像をそのまま入力できない |

**説明の要点**:
- ドローン画像（4000×3000等）を640×640に縮小すると、小さい損傷が数ピクセルに潰れて検出不能になる
- パッチに切ることで、小さい損傷が十分なサイズで保たれる
- 「ピラミッド」= 複数スケールでパッチを作る。大きいパッチで大きい損傷、小さいパッチで小さい損傷をカバー
- 結果: mAP@0.5が0.35 → 0.58（+67%改善）
- 副次効果: 1枚の画像から複数パッチが生まれるため、学習データが増える → 過学習の緩和にも貢献

## Phase C: 評価指標の実践的理解（完了: 2026-04-15）

### 合格ライン1: 混同行列（Fig. 3）で具体例を説明

| 用語 | 意味 |
|---|---|
| 偽陽性（False Positive, FP） | 損傷がないのに「あり」と判定する誤検出。確認の手間が増えるが致命的ではない |
| 偽陰性（False Negative, FN） | 損傷があるのに「なし」と見逃す。致命的な損傷を放置するリスクがある |
| Precision（精度） | 「損傷ありと言ったもの」のうち本当に損傷があった割合。偽陽性が少ないほど高い |
| Recall（再現率） | 「実際に損傷があったもの」のうち検出できた割合。偽陰性が少ないほど高い |

**説明の要点**:
- ブレード点検（スクリーニング用途）では**Recallを優先**。見逃し（FN）が致命的だから
- 用途によって優先する指標が変わる（例: 迷惑メールフィルタではPrecision優先）

---

### 合格ライン2: 「IoU閾値を0.7にしたらmAPはどうなるか」を予測

| 用語 | 意味 |
|---|---|
| IoU（Intersection over Union） | 予測BBoxと正解BBoxの重なり面積 ÷ 合わせた全体面積。1.0で完全一致、0.0で重なりなし |
| IoU閾値 | 「IoUがこの値以上なら正解とみなす」という基準 |
| mAP@0.5 | IoU 0.5以上で正解とみなしたときのmAP。比較的緩い基準 |
| mAP@0.5:0.95 | IoU 0.5〜0.95を0.05刻みで平均したmAP。厳しい基準を含む総合評価 |

**説明の要点**:
- IoU閾値を上げると基準が厳しくなる → 正解とみなされる検出が減る → mAPは**下がる**
- Paper 1の実例: mAP@0.5 = 0.581、mAP@0.5:0.95 = 0.314（厳しくすると大幅に下がる）

---

### 合格ライン3: Paper 1のTable 3で「なぜ2つのmAPを報告しているか」を説明

| 用語 | 意味 |
|---|---|
| AP（Average Precision） | 1クラスのPR曲線下面積。クラス単独の検出精度 |
| mAP（mean Average Precision） | 全クラスのAPの平均。総合的な検出性能指標 |
| 5クラスmAP | 全5クラス（LE;ER, VG;MT, LR;DA, LE;CR, SF;PO）の平均 = 0.561 |
| 4クラスmAP | LE;CRを除く4クラスの平均 = 0.701 |

**説明の要点**:
- LE;CRのAP = 0.00（完全に検出不能）。これが5クラスmAPを引き下げている
- 2つ報告することで「問題がモデル全体にあるのか、特定クラスにあるのか」を区別できる
- モデルの実力は0.70あるが、LE;CRの0が足を引っ張って全体が0.56になっている

---

### 合格ライン4: 「Recall 0.49は実務的に何を意味するか」を説明

**説明の要点**:
- Recall 0.49 = 損傷が100個あったら約51個を見逃す
- スクリーニングツールとしては不十分。半分以上を見逃すのでは実用に耐えない
- Paper 1ではこれを限界として正直に明記している

## Phase D: クラス不均衡と検出失敗（完了: 2026-04-15）

### 合格ライン1: 「LE;CRが1.6%しかないとなぜ検出できないか」を説明

| 用語 | 意味 |
|---|---|
| クラス不均衡 | 学習データの各クラスのデータ量に大きな偏りがあること。LE;CRは全パッチの1.6%しかない |
| 多数派バイアス | データが多いクラスを正解するほうが効率よく損失が下がるため、少数クラスが無視されがちになる現象 |

**説明の要点**:
- 1.6%ではパターンを学ぶ機会が根本的に不足する
- バッチにLE;CRが含まれる確率が極めて低い
- 「全部LE;CRではない」と答えるだけで損失がかなり小さくなるため、モデルが少数クラスを無視する
- 公開データ（DTU）に依存しているため、自分でデータを増やせないという構造的制約がある

---

### 合格ライン2: focal lossを概念レベルで説明

| 用語 | 意味 |
|---|---|
| cross entropy loss | 通常の損失関数。簡単な例も難しい例も同じように損失に寄与する |
| focal loss | 簡単に正解できるもの（確信度が高い）の損失寄与を下げ、難しいもの（確信度が低い）に集中させる工夫 |

**説明の要点**:
- 簡単な例の重みを下げて、難しい例に集中させる
- ただしPaper 1では、focal lossを使ってもLE;CRのAP = 0.00のまま。1.6%という偏りが極端すぎた

### 合格ライン3: 「なぜ物体サイズが原因ではないか」をFig. 9を使って説明

| 用語 | 意味 |
|---|---|
| Table 5（診断表） | LE;CR検出失敗の原因について5つの仮説を検証した表 |

**Paper 1 Table 5 の5仮説まとめ**:

| 仮説 | 結論 | 根拠 |
|---|---|---|
| 物体サイズが原因 | 棄却 | 他クラスにも同サイズの小さい損傷があるが検出できている |
| アノテーション品質が原因 | 部分的 | 一部課題あるが主因ではない |
| モデルサイズが原因 | 棄却 | n/s/mすべてでLE;CR = 0.00 |
| パッチ拡張が不十分 | 棄却 | 拡張後も1.6%は変わらない |
| **クラス不均衡が主因** | **採用** | **1.6%では学習機会が根本的に不足** |

**説明の要点**:
- サイズが原因なら、小さい損傷はクラスに関係なく全部検出できないはず
- 実際にはLE;CRだけがAP = 0.00 → サイズではなくLE;CR固有の問題（データ不足）

### 補足: LE;ERとLE;CRの関係

| 段階 | 状態 | クラス |
|---|---|---|
| 1 | コーティング（ペイント＋フィラー）摩耗、FRP露出 | LE;ER |
| 2 | FRPがさらに損傷（ボコボコに） | LE;ER（進行） |
| 3 | FRP自体に亀裂・割れ | LE;CR |

- LE;ERとLE;CRは独立した損傷ではなく、エロージョン進行段階の連続線上にある
- 注意: DTUデータセットのラベル定義と実務的な段階分けが一致しているかは要確認
