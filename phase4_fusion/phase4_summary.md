# Phase 4 サマリーレポート

**作成日**: 2026-04-02
**対象**: Phase 4 — 画像リスクスコア × SCADA疲労指標 統合パイプライン（型実装）

---

## 1. 設計方針

### なぜ「型」として実装するか

| 問題 | 内容 |
|---|---|
| データの異質性 | 画像データ（DTU・デンマーク・Nordtank）とSCADAデータ（Kaggle・トルコ・別メーカー）は別タービン |
| 直接統合の限界 | 同一タービンでないため、統合結果に統計的な意味が生じない |
| 対処方針 | パイプライン構造のみ実装し、合成データで動作確認。自社データ投入時に即使用可能にする |

---

## 2. パイプライン構造

```
入力A: 画像リスクスコア（スパン別・タービンID・月）
       ← Phase 1/2 の出力 または 自社データ
入力B: SCADA疲労代理指標（タービンID・月）
       ← Phase 3 の出力 または 自社SCADAデータ
         ↓ merge on [turbine_id, month]
統合テーブル
         ↓
相関分析（Pearson / Spearman）
統合リスクスコア算出 = α × 画像リスク + β × 疲労リスク
可視化（散布図・月次棒グラフ・タービン別ランキング）
```

## 5. 重みの設定について

現状は等重み（α=β=0.5）。将来的な改善方向：

| アプローチ | 内容 | 必要条件 |
|---|---|---|

## 6. Phase 5への引き継ぎ

Phase 4の統合スコアに物理的な裏付けを追加するには、OpenFASTによる荷重シミュレーションが必要。具体的には「風速×TI環境に対するブレード疲労荷重」を計算し、fatigue_risk_scoreの重みを物理的根拠で決める。

---

## 7. 制約・限界の自己評価

1. **合成データでの動作確認のみ**：統計的な結論は出せない
2. **等重みの暫定性**：実運用では根拠ある重み設定が必要
3. **月次粒度の粗さ**：短期イベント（暴風・急激な劣化）は捉えられない
4. **単一タービン前提**：複数タービン間の比較は相対評価に過ぎない

これらは論文化・実運用時に「研究の限界」として明示する。
